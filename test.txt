# Experiment 8 – Jenkins: Pipeline Job Integrated with GitHub

## 1. Aim
Create a GitHub repository, install and launch Jenkins locally, install the Git/GitHub/Pipeline plugins, create a Pipeline job configured to read a `Jenkinsfile` from source control, configure a build trigger, push code changes, and verify that Jenkins runs a build automatically.

## 2. Requirements
- Windows computer with internet access.
- Java version supported by the Jenkins LTS release you install. Check the official Jenkins installation instructions for the matching Java requirement.
- Jenkins LTS installed and accessible at `http://localhost:8080`.
- Git installed and available to the Jenkins agent/service.
- A GitHub repository (public is simplest for the lab; private repositories need credentials).
- Python 3 on the Jenkins machine if you want to run the Python syntax-check stage below.

## 3. Step-by-step implementation

### Step 1 – Create a GitHub repository
1. Sign in to GitHub and create a repository named `Jenkins-Pipeline-Demo`.
2. Add a README or a small Python source file.
3. Add `program1.py` with the following simple program:

```python
number = int(input("Enter a number: "))
print("Square:", number ** 2)
```

4. Commit and push the file to the default branch (usually `main`).
5. Copy the repository HTTPS URL.

### Step 2 – Install and launch Jenkins
1. Install a Java Development Kit version supported by the Jenkins LTS release you selected.
2. Install Jenkins using the official Windows installer or the approved lab installation method.
3. Start the Jenkins service.
4. Open a browser and visit `http://localhost:8080`.
5. On first launch, retrieve the initial administrator password from the location displayed by the installer/setup screen. For a standard Windows MSI setup, the setup wizard usually provides the path under the Jenkins installation directory.
6. Enter the password, install the suggested plugins, and create an administrator user.
7. Complete setup and confirm the Jenkins dashboard is visible.

### Step 3 – Install required plugins
1. From the Jenkins dashboard, select **Manage Jenkins → Plugins** (the exact menu label may vary by Jenkins version).
2. Open the Available plugins section.
3. Search for and install:
   - **Git plugin**
   - **GitHub plugin**
   - **Pipeline plugin** (or the Pipeline suite if presented)
4. Restart Jenkins if requested and confirm the plugins are installed.

### Step 4 – Configure Git and Python for the Jenkins agent
On the machine/agent that will execute the job, check:

```bash
git --version
python --version
```

For Jenkins installed as a Windows service, the service account must be able to access Git and Python through PATH. If necessary, configure the Jenkins service to run under an account that has access to those tools, then restart the service.

### Step 5 – Add a `Jenkinsfile` to the GitHub repository
In the root of `Jenkins-Pipeline-Demo`, create a file named exactly `Jenkinsfile` (no extension):

```groovy
pipeline {
    agent any

    options {
        timestamps()
    }

    stages {
        stage('Checkout') {
            steps {
                checkout scm
            }
        }

        stage('Verify Tools') {
            steps {
                bat 'git --version'
                bat 'python --version'
            }
        }

        stage('Python Syntax Check') {
            steps {
                bat 'python -m py_compile program1.py'
            }
        }

        stage('Build Complete') {
            steps {
                echo 'Jenkins pipeline completed successfully.'
            }
        }
    }

    post {
        success {
            echo 'Build passed.'
        }
        failure {
            echo 'Build failed. Check the console output.'
        }
    }
}
```

This example uses `bat` because the assumed Jenkins agent is Windows. On a Linux agent, replace `bat` steps with `sh` steps.

Commit and push the `Jenkinsfile` to GitHub:

```bash
git add Jenkinsfile
git commit -m "Add Jenkins pipeline definition"
git push
```

### Step 6 – Create a Pipeline job in Jenkins
1. Open `http://localhost:8080`.
2. Select **New Item**.
3. Enter job name `Python-GitHub-Pipeline`.
4. Select **Pipeline**.
5. Select **OK**.

### Step 7 – Configure Pipeline script from SCM
1. Open the job's **Configure** page.
2. Find the **Pipeline** section.
3. Set **Definition** to **Pipeline script from SCM**.
4. Set **SCM** to **Git**.
5. Enter the GitHub repository HTTPS URL.
6. Set the branch specifier to `*/main` (use `*/master` if the default branch is `master`).
7. If the repository is private, select or create Jenkins credentials with read access. Do not paste a password or token into the Jenkinsfile.
8. Set **Script Path** to `Jenkinsfile`.
9. Save the job.

### Step 8 – Configure a build trigger
For a local Jenkins instance at `localhost:8080`, **Poll SCM** is the simplest option because GitHub's servers cannot normally call a private `localhost` address.

1. Open **Configure → Build Triggers**.
2. Select **Poll SCM**.
3. Enter a schedule such as:

```text
H/2 * * * *
```

This checks for changes approximately every two minutes, using Jenkins' hash-based scheduling. For a production setup, choose a suitable polling interval or use a properly reachable, secured webhook endpoint.

**Optional GitHub webhook:** A GitHub webhook requires Jenkins to be reachable from GitHub over the internet through a secure, correctly configured endpoint. Do not enter `http://localhost:8080/github-webhook/` in GitHub and expect GitHub's servers to reach your computer; `localhost` refers to the machine making the request.

### Step 9 – Run the first build
1. Open the job.
2. Select **Build Now**.
3. Open **Build History** and select the new build number.
4. Select **Console Output**.
5. Confirm that Git checkout, tool verification, Python syntax checking, and the final message complete successfully.

### Step 10 – Verify automatic triggering
1. Make a small change to `program1.py` or another tracked project file.
2. Commit and push the change to the branch configured in the Jenkins job.
3. Wait for the next Poll SCM check (do not expect an immediate build unless a webhook or manual trigger is used).
4. Refresh Jenkins Build History.
5. Confirm a new build starts automatically and its console output shows the updated revision.

## 4. Expected result
- Jenkins opens at `http://localhost:8080`.
- Required plugins are installed.
- A Pipeline job reads `Jenkinsfile` from GitHub.
- The pipeline checks out the code and runs the Python syntax check.
- A push to GitHub is detected by the configured trigger and starts a new build.

## 5. Common errors and fixes
- **Jenkins does not start:** Check Java compatibility with your Jenkins LTS version and inspect the Jenkins service log.
- **Git executable not found:** Ensure Git is installed and available in PATH for the Jenkins service account; restart Jenkins after PATH changes.
- **Python not found:** Install Python or configure the Jenkins agent PATH. Confirm `python --version` under the same account.
- **Repository checkout fails:** Check the URL, branch name, network access, and credentials for a private repository.
- **Jenkinsfile not found:** Ensure the file is named exactly `Jenkinsfile`, is at the repository root, and is pushed to the configured branch.
- **Poll SCM does not trigger:** Confirm the job is saved with Poll SCM, a commit was pushed to the monitored branch, and allow the polling interval to pass.

## 6. Expected viva questions with answers
1. **What is Jenkins?** – An automation server used to automate building, testing, and delivery tasks.
2. **What is CI?** – Continuous Integration: frequently integrating code changes and validating them with automated builds/tests.
3. **What is a Jenkins job?** – A configured task or pipeline that Jenkins executes.
4. **What is a Pipeline in Jenkins?** – A sequence of automated stages defined as code.
5. **What is a Jenkinsfile?** – A text file in the repository that defines a Jenkins Pipeline.
6. **What is Pipeline as Code?** – Managing the build and deployment process using a version-controlled pipeline definition.
7. **What is the Git plugin used for?** – It enables Jenkins to interact with Git repositories.
8. **What is SCM?** – Source Code Management; it refers to systems that manage source-code versions, such as Git.
9. **What is Poll SCM?** – A trigger that periodically checks the repository for new changes.
10. **What is a webhook?** – An HTTP notification sent by a service such as GitHub when an event occurs.
11. **Why does a webhook not normally reach localhost?** – The GitHub server cannot directly access a developer's private loopback address.
12. **What is a build trigger?** – A condition or event that causes Jenkins to start a build.
